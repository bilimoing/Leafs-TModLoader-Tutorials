# **创建你的物块**

就像新建物品，新建弹幕那样，我们需要在**Content**文件夹下新建一个文件夹，并且起名为**Tiles**，然后新建一个物块类，并继承自`ModTile`。如果你有学习过与物品和弹幕相关的教程的话应该对于这个操作非常熟悉了。但如果你没有学习过任何的物品教程，我推荐你先去看 [物品教程](https://www.kdocs.cn/l/cvR5bzWRr1Sa)，因为在这篇教程中同样会用到相关内容，并且我不会着重介绍它们。

```csharp
using Terraria.ModLoader;

namespace DemoMod.Content.Tiles
{
    public class DemoTile : ModTile
    {
        public override void SetStaticDefaults()
        {
            // 在这里写物块相关设置
        }
    }
}
```

**需要注意**：物块只有`SetStaticDefaults`，并没有`SetDefaults`。

### 设置静态属性

但在模组开发中，这样简单的物块是完全不够用的，所以接下来我们介绍一些较为常用的物块静态属性，以下内容请写在物块的`SetStaticDefaults` 方法中

```csharp
// 帧重要，如果你的物块并非普通的单物块请务必设置为 true!!!
Main.tileFrameImportant[Type] = false;
// 是否为实心物块
Main.tileSolid[Type] = true;
// 为 true 时就不能在它旁边放上物块，例如插火把之类的就不行了
Main.tileNoAttach[Type] = false;
// 顶部是否为实心，就和平台一样，玩家按下"下"时就可以从上面下来
// 请注意这个属性会覆盖掉 tileSolid
Main.tileSolidTop[Type] = false;
// 是否会被近战攻击、弹幕等所破坏
Main.tileCut[Type] = false;
// 是否是桌子，为 true 的话就可以在上面放上玻璃瓶之类的东西
Main.tileTable[Type] = false;
// 是否会和泥土"融合"，请注意这将改变贴图的读取方式
Main.tileMergeDirt[Type] = false;
// 是否会被水冲掉
Main.tileWaterDeath[Type] = true;
// 是否会被岩浆烫掉
Main.tileLavaDeath[Type] = true;
// 是否阻挡光
Main.tileBlockLight[Type] = true;
// 是否能发出闪光粒子，就像矿物一样，另外光照如果太低的话将无法发出粒子
Main.tileShine2[Type] = true;
// 发出闪亮粒子的"频率"，这个数字越大则"频率"越低
Main.tileShine[Type] = 1000;
```

设置完以上属性之后，我们来看看在游戏内的效果吧！

# 掉落物回收

现在我们有了一个可以放置的物块，以及一个能放置这个物块的物品，当这个物块被破坏时，会正常掉落放置物本身。这听上去是不是完全正常？但其实这里面藏着一个小小的隐患。

我们先来看`Item.DefaultToPlaceableTile` 方法的源码：

```csharp
/// <summary>
/// 此方法用于设置放置物块类物品常用的一组 Item 属性。<br/>
/// 具体设置如下：<code>
/// createTile = tileIDToPlace;
/// placeStyle = tileStyleToPlace;
/// width = 14;
/// height = 14;
/// useStyle = <see cref="ItemUseStyleID.Swing"/>;  // 挥动使用样式
/// useAnimation = 15;   // 使用动画时长 15 帧
/// useTime = 10;        // 使用间隔 10 帧
/// useTurn = true;      // 使用时可转身
/// autoReuse = true;    // 自动连发
/// consumable = true;   // 消耗品
/// </code>
/// </summary>
/// <param name="tileIDToPlace">要放置的物块 ID</param>
/// <param name="tileStyleToPlace">要放置的物块样式（用于同一物块的不同外观）</param>
public void DefaultToPlaceableTile(ushort tileIDToPlace, int tileStyleToPlace = 0)
{
    createTile = tileIDToPlace;       // 设置要放置的物块 ID
    placeStyle = tileStyleToPlace;    // 设置物块样式
    width = 14;                       // 物品宽度 14 像素
    height = 14;                      // 物品高度 14 像素
    useStyle = 1;                     // 使用样式为挥动（对应 ItemUseStyleID.Swing）
    useAnimation = 15;                // 使用动画持续 15 帧
    useTime = 10;                     // 使用间隔 10 帧
    useTurn = true;                   // 使用期间允许转身
    autoReuse = true;                 // 按住鼠标可连续放置
    consumable = true;                // 使用后消耗 1 个
}
```

看起来是不是没什么问题？那如果我告诉你：物块的掉落物注册逻辑是，**判断我们的物块有没有掉落物。如果没有，TML 就会通过** **`Item.createTile` 和** **`Item.placeStyle` 这两个属性，自动为我们的物块注册掉落物呢？**



这时候，部分同学可能觉得：“唉，这不是还是没什么吗？”但有些反应快的同学可能已经察觉到问题了。如果我们有多个物品，都用 `DefaultToPlaceableTile` 方法为同一个物块注册使用物，甚至只是单纯用 `Item.createTile = 物块ID` 做一个无限放置物块的魔杖，会发生什么？



答案是：**这就变成了一场多个物品之间有关于加载顺序的“竞赛”。**

哪个物品先被加载，它就会被注册成这个物块的掉落物；而加载慢的物品，哪怕它才是一个贴图、名字都完美对应的“正主”，也会被无情抛弃。

这就是我们在物块制作时候，要手动控制掉落物的原因。



在`SetStaticDefaults` 方法里填入：

```csharp
// 【掉落物设置】
// 如果物块只有单个对应的放置物品（Item.createTile 指向本物块），
// GetItemDrops 会自动掉落该物品，不需要写 RegisterItemDrop。
// 如果没有对应物品，或需要指定多个掉落物，才使用它（尖括号内填你的物品类名）：
// RegisterItemDrop(ModContent.ItemType<MyItem>());
```

就可以设置物块掉落物了。

除了掉落物，我们还可以设置一些`ModTile` 中自带的物块属性：

```csharp
// 【物块属性】
// 物块被挖掘时的音效
HitSound = SoundID.Dig;

// 挖掘时产生的粒子
DustType = DustID.Dirt;

// 挖掘抗性：数值越大，物块越难被破坏
MineResist = 1f;

// 挖掘该物块所需的最小镐力（默认是 0，这里设为 40）
MinPick = 40;
```

物块挖掘的镐力需求可以在：[矿石 - 官方中文 Terraria Wiki](https://terraria.wiki.gg/zh/wiki/%E7%9F%BF%E7%9F%B3) 这个页面里查询。

对镐力相关机制感兴趣的同学可以在：[镐力 - 官方中文 Terraria Wiki](https://terraria.wiki.gg/zh/wiki/%E9%95%90%E5%8A%9B) 中查询更多相关内容。

现在我们就像创建物块文件一样，创建一个平台类继承 `ModTile`吧！以下是这个平台的全部属性设置，同样的属性将不再赘述：

```csharp
using DemoMod.Content.GlowMask;
using Microsoft.Xna.Framework.Graphics;
using Terraria;
using Terraria.ID;
using Terraria.ModLoader;
using Terraria.ObjectData;
using static Terraria.ID.ContentSamples.CreativeHelper;

namespace DemoMod.Content.Tiles
{
    public class DemoPlatform : ModTile
    {
        public override void SetStaticDefaults()
        {
            // 帧重要，平台属于多格/特殊摆放物块，必须设为 true
            Main.tileFrameImportant[Type] = true;
            // 不发光的普通平台
            Main.tileLighted[Type] = false;
            // 顶部为实心，玩家可以站在上面，按下"下"可以从平台上下来
            Main.tileSolidTop[Type] = true;
            // 实心物块，有碰撞
            Main.tileSolid[Type] = true;
            // 不允许其他物块附着在它旁边（比如不能在平台侧面插火把）
            Main.tileNoAttach[Type] = true;
            // 算作桌子，可以往上放玻璃瓶之类的物品
            Main.tileTable[Type] = true;
            // 接触岩浆会被破坏
            Main.tileLavaDeath[Type] = true;

            // 标记为平台，这是平台的核心标识，影响碰撞、摆放和智能光标判定
            TileID.Sets.Platforms[Type] = true;
            // 光标悬停时禁用智能光标，避免误操作
            TileID.Sets.DisableSmartCursor[Type] = true;

            // 让这个物块在房屋检测中算作"门"
            TileID.Sets.RoomNeeds.CountsAsDoor[Type] = true;


            // 其实可以复制原版平台行为：尺寸、坐标、样式、UsesCustomCanPlace、LavaDeath 等整套数据
            // TileObjectData.newTile.CopyFrom(TileObjectData.GetTileData(TileID.Platforms, 0));

            // 物块宽度，单位是格。1 表示占 1 格宽
            TileObjectData.newTile.Width = 1;
            // 物块高度，单位是格。1 表示占 1 格高
            TileObjectData.newTile.Height = 1;
            // 每一格的高度（像素）。数组长度必须等于 Height，这里只有 1 格所以是 { 16 }
            TileObjectData.newTile.CoordinateHeights = new[] { 16 };
            // 每一格的宽度（像素），通常都是 16
            TileObjectData.newTile.CoordinateWidth = 16;
            // 贴图读取时每格之间的间隔像素，原版统一用 2
            TileObjectData.newTile.CoordinatePadding = 2;
            // 样式乘数，用于计算 StyleMultiplier × Style 得到实际读取的贴图列/行
            // 平台设为 27，因为原版平台有 27 种摆放样式
            TileObjectData.newTile.StyleMultiplier = 27;
            // 每行（或每列）最多放多少种样式，超过就换行/换列
            // 平台设为 27，与 StyleMultiplier 保持一致
            TileObjectData.newTile.StyleWrapLimit = 27;
            // 样式是否横向排列。true 表示横向读取贴图，false 表示纵向
            TileObjectData.newTile.StyleHorizontal = true;
            // 是否使用自定义放置检测。false 表示回退到像普通地形物块一样放置
            // 平台设为 false，因为平台的摆放逻辑由 TileID.Sets.Platforms 处理
            TileObjectData.newTile.UsesCustomCanPlace = false;
            // 接触岩浆是否被破坏。true 表示会被岩浆烧掉
            TileObjectData.newTile.LavaDeath = true;

            // 注册上面配置好的 newTile，必须在所有 newTile 修改之后调用
            TileObjectData.addTile(Type);


            // 让这个物块在寻找制作站时作为平台
            AdjTiles = new int[] { TileID.Platforms };
            // 被挖掘时的音效
            HitSound = SoundID.Dig;
            // 被挖掘时产生的粒子
            DustType = DustID.Dirt;
            // 挖掘难度系数，1f 为普通难度
            MineResist = 1f;
            // 挖掘所需最小镐力，0 表示不需要镐力
            MinPick = 0;
        }
    }
    public class DemoPlatform_Item : ModItem
    {
        public override void SetDefaults()
        {
            Item.DefaultToPlaceableTile(ModContent.TileType<DemoTile>());
        }
    }
}
```

### **TileID.Sets**

除了使用`Main.XXX` 来设置物块属性之外，`TileID.Sets.XXX` 同样可以用于设置这个物块的属性，并且这里面的属性超级超级多，但很多都可能是在制作模组时完全用不到的属性。

```csharp
// 是否是一个平台，你同样可以使用这个属性来检测某物块是不是个平台
TileID.Sets.Platforms[Type] = true;
// 当光标悬停在此物块上时，是否禁用智能光标功能
TileID.Sets.DisableSmartCursor[Type] = true;
// 记为门
TileID.Sets.RoomNeeds.CountsAsDoor[Type] = true;

// 记为椅子
// TileID.Sets.RoomNeeds.CountsAsChair[Type] = true;
// 记为桌子
// TileID.Sets.RoomNeeds.CountsAsTable[Type] = true;
// 记为火把
// TileID.Sets.RoomNeeds.CountsAsTorch[Type] = true;
```

平台居然都算作"门"，泰拉瑞亚，很神奇吧。这也是那种监狱式房屋能被房屋检测记为合适房间的原因。`TileID.Set` 中的其他属性都是用来干什么的等到后续教程中用到了再说吧。

### **TileObjectData**

`TileObjectData` 是物块内容中一个极为重要的部分，你可以使用它来更加自定义化你的物块，但鉴于这是一个基础教程，所以我只讲一些基本的内容，更多有趣的内容将在后续教程中介绍。

> [⚠️]  
> 注：如果你使用了 `CopyFrom(GetTileData(TileID.Platforms, 0))` 后，这一整段`TileObjectData`不需要手写了，原版数据已经包含了相关内容。只有你自己从零做多格物块时才需要手动设置这三项。  

首先，`TileObjectData` 的使用基本可以分为3部分，分别是 `newTile`，`newSubTile` 和`newAlternate`。

绝大多数时候我们只需要使用`newTile`。`newSubTile` 仅在你想把多个物块贴图塞在一张图中并且想让这些物块拥有不同的属性时才会使用到。至于最后的`newAlternate`，只有在你想让一个物块能有多种摆放方式时才会用到它。举个例子，我想让一个告示牌既可以插在地上，又能吊在天花板上，就可以使用`newAlternate` 去设置对应的摆放状态。

扯远了，还是详细说一下`newTile` 中可以设置的各种属性吧。

#### 物块大小

```csharp
TileObjectData.newTile.Width = 1;                       // 宽多少格
TileObjectData.newTile.Height = 1;                      // 高多少格
TileObjectData.newTile.CoordinateHeights = new[] { 16 }; // 每格高度，必须和贴图匹配
TileObjectData.newTile.CoordinateWidth = 16;            // 每格宽度
TileObjectData.newTile.CoordinatePadding = 2;           // 贴图读取间隔
```

**这只是一个示例**，你也可以试着跟着设置一下看看效果。但是请保证你的贴图大小和你的设置相匹配，否则将导致绘制时出现BUG，甚至会使游戏直接崩溃。

#### 物块 Style

```csharp
// 比较玄幻的属性，一般和下面那个保持一致即可

TileObjectData.newTile.StyleMultiplier = 27;
```

#### 其他设置

`TileObjectData.newTile.UsesCustomCanPlace = false;`：一般应设为 `true`。原文设为 `false` 是因为测试时发现设为 `true` 平台能隔空摆放，这大概是因为没设置与摆放相关的 `AnchorXXX` 属性。与摆放相关的 `AnchorXXX` 系列将在后续教程介绍。

`TileObjectData.newTile.LavaDeath = true;`：和 `Main` 中一样，这里也有判断物块是否被岩浆破坏的属性，主要用于子物块。大多数平台共用一个物块 ID（19），但仅黑曜石平台和石平台防岩浆，就是因为用 `newSubTile` 额外设置了这个属性。

`TileObjectData.addTile(Type);` **极为重要！极为重要！极为重要！** 它把上面所有对 `newTile` 的修改"注册"上去。确保修改设置后加上这一行，**并在这一行之后不要再对** **`newTile` 做任何修改**。



`AdjTiles = new int[] { TileID.Platforms };`：`ModTile` 提供的属性，把该物块标记为指定制作站。大括号内填物块 ID，用逗号隔开。这里表示该物块在搜寻制作站时作为平台。

试着改成让你的物块被当作铁砧（提示：铁砧的物块 ID 叫 `Anvils`）。

# `Main` 中的其他设置

鉴于内容比较多，所以不重要的属性就暂时不介绍了。未注明的均为`bool` 类型，且默认`false`。

```csharp
// 使用示例
Main.tileLighted[Type] = true;
```

- **`Main.tileLighted`**：是否会发光。为 `true` 时可用下面的重写方法自定义发出的光。

  ```csharp
  public override void ModifyLight(int i, int j, ref float r, ref float g, ref float b)
  {
      // 在这里添加自定义内容
  }
  ```

- **`Main.tileAlch`**：是否为草药（太阳花、闪耀根等）。记住 `Alch` 代表草药，后续教程中也会用到。

- **`Main.tileStone`**：为 `true` 表示该物块能和石头融合，或材质就是石头。各种宝石矿物用到它。

- **`Main.tileAxe`**：是否能用斧头挖掘。

- **`Main.tileHammer`**：是否能用锤子挖掘。原版仅恶魔祭坛和暗影珠/猩红之心用到。

- **`Main.tileNoSunLight`**：是否阻挡太阳光。类似玻璃、云等设为 `false`。如果 `tileSolid` 为 `true`，会自动把这项设为 `true`。

- **`Main.tileObsidianKill`**：是否会在生成黑曜石时被挤掉。如果 `tileLavaDeath` 为 `true`，会自动把这项设为 `true`。

  以上两个属性如需进一步自定义（比如 `tileSolid` 为 `true` 时 `tileNoSunLight` 为 `false`），用 `ModTile` 的重写方法：

  ```csharp
  public override void PostSetDefaults()
  {
      // 在这里进一步自定义上面两个属性
  }
  ```

- **`Main.tileDungeon`**：是否为地牢砖。影响部分 NPC 生成和物块被挖掘时受到的"伤害"，这也是地牢砖比较难挖的原因。

- **`Main.tileSpelunker`**：是否能被洞穴探测药水等探测到。更自定义可用：

  ```csharp
  public override bool IsTileSpelunkable(int i, int j)
  {
      // 这里写的是只有白天才会被探测到
      if (Main.dayTime)
          return true;
  
      return false;
  }
  ```

- **`Main.tileBouncy`**：物块是否 Q 弹。为 `true` 时玩家掉上去会弹起来。

- **`int Main.tileOreFinderPriority`**：默认 `0`，金属探测器检测优先度。数值越大越优先显示，具体设置查阅泰拉 Wiki 金属探测器页面。

- **`Main.tileRope`**：是否为绳子。为 `true` 时玩家可以爬。

- **`Main.tileNoFail`**：物块不会失败？其实是为`true` 时该物块就一定能被挖掉，无视镐力之类的，确实是不失败嗷。
