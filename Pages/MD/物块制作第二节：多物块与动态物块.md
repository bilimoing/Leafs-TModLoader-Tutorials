# **多物块**

什么是多物块？这里指**宽度或高度大于一格**的物块。注意：帧图较大并不意味着它是多物块。比如原版珊瑚的贴图长宽都大于 16，但它仍然是单格物块。

### 删除掉落物

**Stop！ 先等一下！**我们好像忘了，这个自制巨石被挖掉以后，是会掉落回它对应的物品的啊。但对于巨石来说这是错误的。所以，我们要删除它的掉落物。

有些同学可能想到了：`RegisterItemDrop` 传空，这样子，物品的掉落物就会变成空气，这个物块不就不掉落任何物品了吗？

```csharp
// 【掉落物设置】
// 如果物块只有单个对应的放置物品（Item.createTile 指向本物块），
// GetItemDrops 会自动掉落该物品，不需要写 RegisterItemDrop。
// 如果没有对应物品，或需要指定多个掉落物，才使用它（尖括号内填你的物品类名）：
// RegisterItemDrop(ModContent.ItemType<MyItem>());
```

但很可惜，我们不能直接用 `RegisterItemDrop`。因为它**默认值就是传空**，而系统会把“传空”视为“未注册”，从而自动触发后备掉落或自动掉落逻辑。

要实现“不掉落任何物品”，**TModLoader** 为我们提供了专门的办法，我们在  **物品**  里写上：

```csharp
public override void SetStaticDefaults()
{
    // 禁止物块的自动掉落物绑定
    ItemID.Sets.DisableAutomaticPlaceableDrop[Type] = true;
}
```

然后物块就会因为检索不到使用它的物品，就失去自动掉落物啦。不过，如果你有多个可以 **放置相同物块** 的物品，或者是想在 **特定条件下** 不掉落（比如物块处于某个高度时），或者想彻底接管掉落逻辑，也可以重写 `ModTile` 的 `CanDrop` 方法：

```csharp
public override bool CanDrop(int i, int j)
{
    // 返回 false 表示该物块在此刻被破坏时，不执行任何掉落逻辑
    // 你可以在这里写自定义条件，比如：
    // if (someCondition) return false;
    
    return true; 
}
```

不过在我们目前的教程里，只需要在物品加 `ItemID.Sets.DisableAutomaticPlaceableDrop[Type] = true;`，然后**不要在物块里调用** **`RegisterItemDrop`**，这样，这个物块被破坏时就会干干净净，什么都不掉落了。

### **KillMultiTile**

如果你对巨石有些了解，相信你应该知道会滚动的巨石它其实是个弹幕。所以我们的任务就是在这个物块被破坏时生成一个巨石弹幕。使用下面这个重写方法来在多物块被破坏时执行一些操作，比如生成物品，弹幕等，它 **仅在多物块被破坏时** 被调用**一次**。

```csharp
public override void KillMultiTile(int i, int j, int frameX, int frameY)
{
    // 伤害、击退等你可以随意调整
    Projectile.NewProjectile(new EntitySource_TileBreak(i, j), new Vector2(i + 1, j + 1) * 16,
        Vector2.Zero, 1013, 100, 5f);
}
```

注意：该方法提供的 `i` 和 `j` 是**多物块最左上角**的物块坐标，所以要加 1 得到巨石中心。物块坐标转世界坐标只需乘 16，也可以用泰拉给 `Vector2` 加的扩展方法 `ToWorldCoordinates`，这两个参数默认是 8，我们不需要这个额外偏移，所以要将其设为 0。

### **Anchor系列**

首先是用于判断放置时该物块上下左右有没有指定类型的物块的属性，分为`AnchorTop`，`AnchorBottom`，`AnchorLeft` 和`AnchorRight`。它们都是`AnchorData` 类型的变量，要设置它们你需要自己`new` 一个出来，它的构造器一共需要提供3个变量，分别是什么样的物块，多少个物块和偏移量：

```csharp
/// <summary>
/// 定义一个锚点（Anchor），即多格物块（multitile）在某个位置可放置时，周围必须具备的物块条件。
/// <paramref name="type"/> 决定哪些类型的物块可以作为锚点；
/// <paramref name="start"/> 和 <paramref name="count"/> 决定多格物块的边缘需要有多少格满足该锚点条件。
///
/// 例如，大多数家具类物块会简单地设置一个底部锚点，要求下方一整排都是实心物块：
/// <br/><c>TileObjectData.newTile.AnchorBottom = new AnchorData(AnchorType.SolidTile, TileObjectData.newTile.Width, 0);</c>
/// <br/><br/> 
/// 对于上和下锚点，<paramref name="start"/> 和 <paramref name="count"/> 是从左到右计算的；
/// 对于左和右锚点，则是从上到下计算的。
///
/// <para/> 
/// <paramref name="type"/> 可以使用逻辑或运算符（<c>|</c>）组合多个 <see cref="AnchorType"/> 值，
/// 这样只要满足其中任意一种锚点类型即可：
/// <br/><c>AnchorType.SolidTile | AnchorType.SolidWithTop | AnchorType.SolidSide</c>
///
/// <para/> 
/// 更多信息和可视化示意图，请参阅
/// <see href="https://github.com/tModLoader/tModLoader/wiki/Basic-Tile#anchorbottomanchorleftanchorrightanchortop">
/// 基础物块 Wiki 指南的锚点章节</see>。
/// </summary>
/// <param name="type">锚点类型（可用 | 组合多个）</param>
/// <param name="count">需要满足该锚点条件的格数</param>
/// <param name="start">从边缘的哪一格开始计算（上/下锚点从左往右，左/右锚点从上往下）</param>
public AnchorData(AnchorType type, int count, int start)
{
    this.type = type;       // 锚点类型（哪些物块可以作为支撑）
    tileCount = count;      // 需要的格数
    checkStart = start;     // 起始偏移量
}
```

首先是什么样的物块，各种类型详见下图，如果需要多种类型，它们之间应该使用`|` 连接，并且不可以使用`&` ，其中涉及到比较麻烦的位运算

|**枚举名称**|**十六进制**|**十进制**|**说明**|
|---|---|---|---|
|`None`|`0`|`0`|无锚点。|
|`SolidTile`|`0x1`|`1`|实心物块：是实心，但不是平台/无法附着/斜坡（除非 `FlattenAnchors` 为 true）。|
|`SolidWithTop`|`0x2`|`2`|上方有表面的物块：平台，以及既是实心又上方有表面的物块（如种植盆、金属条）。|
|`Table`|`0x4`|`4`|桌子类物块：是桌子，但不是平台；<br>同时也包含 `SolidWithTop` 的物块。|
|`SolidSide`|`0x8`|`8`|侧面是完整的实心物块：是实心但不是平台；只要锚定的那一侧不是斜坡就行。|
|`Tree`|`0x10`|`16`|树木。|
|`AlternateTile`|`0x20`|`32`|额外放置块，能够让物块放置在设置了：`TileObjectData.AnchorAlternateTiles` <br>的物块上，比如开关能够放在横梁上|
|`EmptyTile`|`0x40`|`64`|没有物块，或者物块被制动器（actuator）关闭。|

|`Platform`|`0x100`|`256`|任意平台物块；横幅类常用它做替代放置，配合 `SolidBottom` 和 `DrawYOffset` 调整高度。|
|`PlanterBox`|`0x200`|`512`|仅限种植盆。|
|`PlatformNonHammered`|`0x400`|`1024`|类似 `Platform`，但不允许被锤过的平台；用于宽度超过 1 格的横幅。|
|`AllFlatHeight`|`0x800`|`2048`|确保所有锚点在同一垂直高度；仅适用于平台，且仅适用于顶部锚点。|

#### AnchorType枚举理论部分

你可以简单地把`AnchorType`里的内容理解为：**物块需要满足什么条件才能放置**。`|` 的效果类似于 `if` 里的 `||`，都是“满足其中任意一个即可”，不是“必须同时满足两个”。所以 `SolidTile | SolidSide` 得到的是一个“既可以放置在实心物块，又可以放置侧面完整（敲过）的实心物块上游戏拿它去比对上方物块时，命中任意一个（满足任意条件）就算通过。

> [⚠️]  
> 但要注意：**这只是帮助你建立直觉的类比，`|` 和** **`||` 不能当成同一个东西**。`|` 在这里是位掩码（bitmask）的用法，不是逻辑判断。`||` 的结果只有 `true` / `false`，而 `|` 的结果是一个**组合后的枚举值**，每个二进制位代表一个选项，游戏后续用按位与 `&` 去逐位检查，而不是直接拿它当布尔值用。  

也正因为如此，**你不能用** **`SolidTile & SolidSide` 来表达“两个条件都要满足”**。`&` 在 `[Flags]` 枚举上是按位求交集，不是逻辑与：

```csharp
SolidTile = 0000 0001
SolidSide = 0000 1000
SolidTile & SolidSide = 0000 0000  // 结果是 AnchorType.None
```

听不懂也没关系，只要记住`AnchorType`：

- **只可以用  \|  写多个条件下，满足任意一个条件**

- **不可以用 &amp; 写多个条件下，同时满足所有条件**

#### 检查数量与检查起始点

至于方法后面的 `count` 和`start` 两个变量意思是按照检查数量与检查起始点，后面有多少个连续多少格满足条件，比如我们代码：

```csharp
// 顶部锚定：要求上方 2 格范围内是实心物块或实心侧面，count=2、start=0
// 这样灯笼只能挂在上方有实心物块的地方
TileObjectData.newTile.AnchorTop = new AnchorData(AnchorType.SolidTile | AnchorType.SolidSide, 2, 0);
```

意思是：从左上角0,0 开始 0,1 结束 这两个位置，上方的物块是不是都满足条件？如果都满足就可以放置物块，`TileObjectData.newTile.AnchorTop` 的 `AnchorTop` 是用来确定方向的：

```csharp
TileObjectData.newTile.AnchorLeft = new AnchorData(AnchorType.SolidTile | AnchorType.SolidSide, 4, 4);
TileObjectData.newTile.AnchorRight = new AnchorData(AnchorType.SolidTile | AnchorType.SolidSide, 2, 2);
TileObjectData.newTile.AnchorTop = new AnchorData(AnchorType.SolidTile | AnchorType.SolidSide, 2, 2);
TileObjectData.newTile.AnchorBottom = AnchorData.Empty;
```

- `AnchorTop` / `AnchorBottom`：会沿**水平方向**检查 `count` 格。

- `AnchorLeft` / `AnchorRight`：会沿**垂直方向**检查 `count` 格。

  

  我们代码的意思是在 `(0，0)` 点开始沿 **水平方向，向右 →** **检查**：

  ```csharp
  上方空间：[格0] [格1] [格2] [格3] .... [格100]
  count=2, start=0 → 检查 格0、格1
  count=2, start=1 → 检查 格1、格2
  count=1, start=2 → 只检查 格2
  ```

  `start = 0` 是最常见的，表示从物块正上方第一格开始数，不过要注意

- `start` **不能大于** `count`，也不能是负数，否则会数组越界报错。

- `count` 不能超过物块在该方向上的尺寸太多，否则永远放不下去。

  

#### 其他属性

**`bool AnchorWall`**放置在墙上的物块把这个设置为`true` 就行，比方说画之类的。

**`int[] AnchorValidTiles`** 设置后，只有目标物块是你指定的物块时才能放置。建议配合上面的 **`AnchorTop`** 等使用。比如树苗下面必须是实心物块，而这个物块又必须是各种草方块才能放下。

**`int[] AnchorInvalidTiles`**：和上面类似，不过反过来了，他是不能放置在指定物块上。

**`int[] AnchorAlternateTiles`**：设置不同摆放样式时额外能放置在哪些物块上。比方说我想让它右边只能是 实心物块和椅子，可以这样设置。`AnchorType.AlternateTile` 也就是专门为它准备的。

```csharp
TileObjectData.newTile.AnchorRight = new AnchorData(AnchorType.SolidTile | AnchorType.SolidSide |
        AnchorType.AlternateTile, 2, 0);
TileObjectData.newTile.AnchorAlternateTiles = new int[] { TileID.Chairs };
```

**`int[] AnchorValidWalls`**：字面意思只有指定墙壁才能放下，但原版没有任何物块用到它。

### RightClick

终于是讲完枯燥的基础设置了，接下来就来做些有趣的吧。首先我们想让这个灯笼能右键开关，实际上就是改变它的帧图，使用下面这个重写方法。

```csharp
public override bool RightClick(int i, int j)
{
    // 为什么是 36？因为贴图一帧总宽度为 2*18=36，中间空的也要算上
    short changeFrames = 36;

    // 这两个表示玩家右键到多物块的具体哪一块，用来得到物块左上角
    // 同时用 X 判断灯笼当前处于第一帧还是第二帧
    // TileFrameX 和 TileFrameY 单位都是像素，与贴图完全对应
    int mouse2TopLeftX = Main.tile[i, j].TileFrameX / 18 * -1;
    int mouse2TopLeftY = Main.tile[i, j].TileFrameY / 18 * -1;

    // 如果小于 -1，说明灯笼现在处于第二帧，要把它变回去，所以 -36 回到第一帧
    if (mouse2TopLeftX < -1)
    {
        mouse2TopLeftX += 2;
        changeFrames = -36;
    }

    // 加上 i 和 j 得到多物块左上角位置
    mouse2TopLeftX += i;
    mouse2TopLeftY += j;

    // 从左上角向右下角遍历，改变帧图
    for (int x = mouse2TopLeftX; x < mouse2TopLeftX + 2; x++)
        for (int y = mouse2TopLeftY; y < mouse2TopLeftY + 2; y++)
            if (Main.tile[x, y].TileType == Type)
                Main.tile[x, y].TileFrameX += changeFrames;

    // 记得返回 true 哦！
    return true;
}
```

这部分需要比较多的思考，建议自己代入数据算一算，同时要多尝试，虽说出问题的话很可能游戏就直接崩溃了，但试错是**不可避免**的，如果有能力的话也可以去看看源码里那些个会动的物块怎么写的。

### **AnimateTile**

接下来就来尝试做一个真正会自己动的物块吧，这部分还是要靠发挥你的想象力，我这里只是做一个简单的效果。

首先使用`AnimateTile` 这个重写方法提供的2个引用变量来改变这个物块的“帧”和“帧计数”2个属性，这两个属性可以通过`Main.tileFrame` 和`Main.tileFrameCounter` 来获取到，但它们实际上并不会直接改变物块的帧图。

```csharp
public override void AnimateTile(ref int frame, ref int frameCounter)
{
    frameCounter++;

    // 这里写的是每 30 帧切换一下
    if (frameCounter >= 30)
    {
        // 在 0 到 1 之间切换，因为灯笼只有 2 帧
        frame = frame switch
        {
            0 => 1,
            1 => 0,
            _ => 0
        };

        frameCounter = 0;
    }
}
```

改变了属性之后接下来自然就是要使用啦，用下面这个重写方法来使用它们，这个重写方法在多物块的每一格物块上都会执行。

```csharp
public override void AnimateIndividualTile(int type, int i, int j, ref int frameXOffset, ref int frameYOffset)
{
    // frameXOffset 和 frameYOffset 决定这一格绘制时贴图偏移多少像素
    // 根据帧改变所有物块帧，这个 Main.tileFrame[type] 就是上面的 frame
    frameXOffset = Main.tileFrame[type] * 36;
}
```
