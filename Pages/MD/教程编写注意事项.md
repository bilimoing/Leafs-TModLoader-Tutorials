# 1投稿与审核流程

如果你想参与教程编写，请加入审核群申请文章审核。

### **大致流程如下：**

- **申请加入**：进入审核群，说明来意以及你想要编写的内容。

- **内容编写**：审核通过后，即可开始编写（也可以直接提交写好的教程文件进行审核）。

- **确定发布方式**：确认文件的公开方式。是由我们这边修改并上传你的文章，还是你提供链接，我们在主页为你挂起。

- **等待通知**：提交后请耐心等待审核结果。

  > [💡]  
  > **注**：一般不建议仅提供外部链接。因为外部链接权限单向，我们无法直接修改，存在较大风险，较难通过审核。  
  
### **申请附带信息：**

- **在教程中使用的用户名**

- **想要贡献的教程题目**

- **你对这个主题的想法**

- **一份内容大纲**

### 文章内容信息：

一般来说，我们希望你对所写的主题有足够的经验和认识。**你所写下的每一行代码，你都要能清楚地解释为什么它们能实现想要的效果。** 如果以“因为 XXX MOD 也是这么写的，我就抄过来”为理由，显然是不够的。

如果你参考了其他地方的代码，请确保你完全理解它的运作逻辑，并用**人类可读**的方式表达出来。

虽然教程文档大部分内容是关于代码的，但是我并不要求一定是代码教程。**绘制、策划、错误处理**等内容也是欢迎的，甚至可以制作一些与泰拉瑞亚无关，但是涉及游戏开发、计算机科学方面的高级内容。

# 2 内容编写要求

- **合规性**：不得涉及任何政治敏感、暴力、色情、人身攻击等与教程无关的内容。

- **图文并茂**：推荐多使用图片辅助说明；推荐加入 GIF 等动画，帮助开发者更直观地理解。

- **通俗易懂**：推荐以容易理解的方式讲述内容，避免过度学术化。

- **代码注释**：推荐给出实现代码，并加上清晰的注释。

- **原创与重构**：无论你的代码是不是参考了别处，都推荐你用自己的理解重写一遍，确保能达到一样的效果。不要在代码中出现明显的“照搬”痕迹（比如生搬硬套的命名）。

- **最终解释权：**归文档维护者所有。

# 3格式与排版规范

教程应保持简单易懂的排版。请使用 Markdown 标题语法（`#`、`##`、`###`）来组织文章结构，系统会根据标题自动生成大纲。**避免使用花里胡哨的字体大小和颜色。**

### 代码相关

- **短代码**：如果内容是代码元素，使用行内代码（用反引号包裹），如 `damage`。

- **长代码**：较长代码请使用代码块，并在开头的反引号后标注语言以启用语法高亮（例如 `csharp`）。

  ```csharp

  ```

  ```javascript

    bgLayerOrder: 'colorOnTop' | 'imageOnTop'  // 图层顺序
  }
  ```

- **代码留白**：对于内嵌短代码，保证左右各留出一个空格，如 `item.damage = 100`。如果一端是一行的开头，或标点符号等已经留出空间，则无需再加空格（如 `this.enableLock`）。

- **代码换行**：一行代码推荐不超过 80 个字符。可以选择在合适的地方换行以增加可读性；如果代码包含太多细节，可以使用伪代码来简化长度、突出总体逻辑。

- **缩进要求**：代码块要使用正确的缩进。推荐先在 Visual Studio (VS) 中写好并格式化，然后复制到代码块中。（VS 里可以用 `Alt + 长按鼠标` 选择一个特定的区域）。
